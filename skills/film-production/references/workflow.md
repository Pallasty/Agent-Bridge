# 按制作阶段使用

这些是本地工作约定；用户的具体交付要求决定哪些阶段需要展开。

| 阶段 | 必须明确的决策 | 制作记录与推进条件 |
|---|---|---|
| 任务简报 | 受众、核心感受、片长、画幅、渠道、截止日期和预算 | 填 brief；保留用户明确的约束和当前授权范围，未知项标 null |
| 剧本与场次 | 每场的叙事目的、对白、时空、角色与难点 | 剧本文件有 revision 和 SHA256；修改时记影响的场次，避免只改摘要 |
| 角色与场景 | 身份、服饰、声音、地点布局、道具、状态变化 | 在 bible 中分开写稳定属性与状态版本；为实际参考文件登记来源、用途、版本和哈希 |
| 分镜与预演 | 构图、视线、轴线、动作、起止状态、剪辑点和声音 | 每镜头有独立 ID；先用镜头表/草图/animatic 检查节奏与空间，再投入高成本生成 |
| 生成计划 | 平台和模式是否支持需要的参考输入、时长、动作与声音 | 查当前接口；按已授权预算设置尝试上限，优先验证最不确定的困难镜头 |
| 生成与选片 | 本次要解决哪一个可观察问题 | 每次尝试记录请求、参数、输入版本、输出、耗时、实际费用和评审；输出文件存在不等于选片通过 |
| 剪辑与声音 | 镜头顺序、对白节奏、环境声、音效、配乐、字幕与调色 | 记录剪辑工程/时间线引用和音频来源；音频需求从剧本/分镜阶段开始规划 |
| 验收与归档 | 是否满足简报，是否可在目标设备播放 | 完整观看与听音、核对规格/字幕/授权、记录用户意见；保存工程、选片清单和交付文件哈希 |

## 单镜头输入包

从项目文件组装，不复制整部影片的历史：

- `shot_id`、剧本版本与当前剧情作用。
- 镜头中的角色、地点和道具引用及其实际参考文件；说明每张参考图用于身份、空间、服饰、动作或风格，避免参考职责混淆。
- 镜头开始/结束状态、上一镜头的衔接要求；角色站位、朝向、道具归属、空间锚点与光线。
- 动作节拍、镜头语言、对白/声音与可观察的验收条件。
- 当前平台所需的参数与输入格式；不要把某一平台的长提示词、焦距写法、seed 行为当作通用规则。

先提出一个具体修正假设，再决定修改提示词、参考图、分镜、模型或剪辑。不要把所有失败都归因为提示词太短；按问题检查身份参考、构图、动作复杂度、时间分配和输入模式。

## 版本变化后

`script revision / asset id + version → shot → generation → selection → edit / delivery`

依据该依赖关系标记需要复核的镜头与交付。不要自动覆盖已选结果，也不要因为新生成的文件较新就替换旧版。保留失败尝试，以便知道哪些约束已经试过。

## 经验是否值得提升为规则

先记录为案例：任务条件、模型/平台版本、失败表现、一次明确改动、前后输出和人工结论。后续真实任务再次支持它时再考虑成为默认建议。比较返工时间和合格镜头成本时，需要同一质量标准，并计入失败生成与人工筛选；不把平台宣传成本或成功样片当作我们的实测。
