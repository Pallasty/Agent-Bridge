# Harness² borrowing: ordinary-task adoption

## Current delivery

The owner asked to implement the next feasible Harness² goal after four local
increments: execution contrast, candidate helper checks, provenance-hidden
artifact comparison and experience draft export. The underlying reported
problem remains goal drift and repeated detail work after several exchanges.
The prior session retrospective establishes examples, not a 30-day frequency
or measured per-occurrence owner cost; both remain unknown.

This increment connects those existing tools to `GOAL_REVIEW.md`, which is
already linked by the repository working instructions. It changes the route
from adding another mechanism to using the retained capabilities selectively.
Reason: the active roadmap prohibits sequential synthetic-only stages from
standing in for use-value evidence. The current user request authorizes
continued work; it does not supply evidence of benefit or a new runtime scope.

The smallest closure is an accessible procedure that lets the working agent
choose a relevant tool or skip all of them, retain one bounded candidate and
unchanged acceptance, and return to the user's deliverable. Without this
connection, another helper could prolong the detail loop it aims to address.

## Application to this task

- Delivery: make the existing helpers usable at ordinary goal-review decision
  points, with a clear stop and return path.
- Baseline: four documented tools with separate entry points; no single
  ordinary-task routing section in the goal-review procedure.
- Change: one routing section plus an evaluation README link. No new command,
  runtime behavior, collection campaign or memory promotion.
- Sufficient check: inspect the route against each tool's actual contract,
  verify local links and confirm the referenced CLI entry points load.
- Stop: once those checks pass, commit this documentation increment. Do not
  add an orchestrator, generate artificial executions or select another stage.
- Not applicable: candidate static check (no skill edit), artifact selection
  (no competing complete outputs), execution contrast (no paired real runs),
  lesson export (no supported general improvement claim).

This is agent-reported application of the routing procedure to an actual task,
not independent acceptance or proof of reduced drift. No comparative cost or
owner-intervention baseline is available. Skipping inapplicable tools is not a
failed experiment and supplies no `helped` observation.
