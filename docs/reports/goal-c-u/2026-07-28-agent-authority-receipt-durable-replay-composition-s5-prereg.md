# Agent authority receipt durable-replay composition S5 preregistration

Date: 2026-07-28

Status: **FROZEN_BEFORE_IMPLEMENTATION**

## Research question

Can the exact signed identity of the S3 public-test receipt be carried into the
existing S7 SQLite replay transaction, including restart and real process-crash
windows, without trusting S3 expected labels or caller-authored S4 transaction
fields?

## Hypothesis

A test-only adapter can independently run the frozen S3 verifier, derive S7's
three fixed commitments only from the verified typed claims, and preserve S7's
fail-closed outcomes under restart, collision, result loss, and SIGKILL.

The hypothesis is false if any caller-selected identity reaches the registry,
if an ineligible receipt produces a request, if a crash produces two successes
or burns a pre-commit request, or if the implementation creates a non-test
receiver capability.

## Planned implementation

1. Add store feature
   `agent-authority-s5-durable-replay-composition-synthetic`, depending on S7.
2. Register one module only under
   `cfg(all(test, feature = "..."))`.
3. Include the frozen S3 example inside a private nested test module and expose
   only a local verified-identity projection.
4. Parse and validate the S5 fixture with `deny_unknown_fields`.
5. Derive transaction, scope, and payload commitments after S3 verification
   and strict consume-time checks.
6. Call only S7's existing private test provisioning/opening and
   `CandidateReplayRegistryV1::consume_once`.
7. Add two ignored helper tests used only as actual child processes by the
   parent pre/post-commit SIGKILL tests.
8. Add no non-test API, path, constructor, runtime caller, or state migration.

## RED contract

Before implementation, a focused compile must fail because the S5 composition
module/API does not exist. The RED must not be produced by malformed JSON,
missing frozen inputs, dependency download, or an unrelated crate failure.

## Expected focused tests

Eight non-ignored S5 tests and two ignored process helpers:

1. frozen sources, counts, commitments, and all-false authority are exact;
2. S3 verification and the exact allowlist precede commitment derivation;
3. seven S4 reviewable steps have zero end-to-end identity matches;
4. both exact receipts commit once and reject replay after reopen;
5. signed-scope and canonical-payload substitution collide without overwrite;
6. post-commit result loss is indeterminate and then replay;
7. pre-commit SIGKILL rolls back and permits one later first consume; and
8. post-commit SIGKILL preserves the tombstone and rejects replay.

The inherited S7 12-test parent matrix and S4 through S0 focused regressions
remain separate gates.

## Hard boundary

All work is reversible local code/schema/test/documentation on an isolated
feature branch. No production/private key, signing operation, credential,
KMS/HSM, live `state.db`, production replay path, StateStore/Bridge/MCP/CLI/
daemon caller, runtime/shadow/executor integration, deployment, authority
grant, master merge, or irreversible external effect is part of S5.
