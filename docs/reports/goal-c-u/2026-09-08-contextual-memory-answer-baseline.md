# 情境记忆实际回答基线

日期：2026-09-08。状态：已完成实际回答、两次独立会话审阅与一次有界检索诊断；保留严格评分 FAIL，未改变生产运行时。

## 本轮目标与固定流程

在已经通过的情境契约基础上，让真实 Codex 会话使用实际 Agent-Bridge 检索结果回答 12 个合成请求，定位记忆支持回答的缺口。先执行基线，再决定是否存在值得修复的可复现问题。

源输入为 [13 条合成经历与 12 个请求](../../../scripts/eval/fixtures/contextual_memory_answer_stimuli.json)。六组分别改变接收者及细节要求、任务相关性、请求时点、项目、执行/回顾意图、推断/验证时点。对应的 [评分义务](../../../scripts/eval/fixtures/contextual_memory_contract.json) 沿用上一轮，不能根据模型回答修改正确答案。

固定步骤：

1. 使用安装的 `agent-bridge.real` 和全新合成 SQLite 存储，记录实际版本与文件哈希。MCP 子进程使用明确的环境白名单与空凭据文件，不调用模型整理记忆。关闭种子进程后通过 SQLite backup 建立基准快照。
2. 每个案例从同一基准快照复制存储，固定调用 `memory_search`：`hybrid`、`local_only`、`limit=8`、`compact=false`。查询来自输入的 `query`，不使用评分器的必需证据列表补检索。
3. 使用确定性的 `hash` embedding 后端，记录实际库中的后端身份。本轮不测量生产 ONNX 语义质量。每组查询和 scope 相同，刻意保持检索刺激一致；本轮也不评价 Agent 自主设计查询或何时调用工具。
4. 每个请求启动一个全新 Codex 会话，使用本机当前配置的 `gpt-6-astra`、medium reasoning；禁用用户配置、规则导入、记忆 hooks 与外部工具，使用空工作目录。实际请求模型、CLI 版本、返回的使用量与会话事件均保留。所有正式调用均实际完成；CLI 未返回实际模型身份，因此仅报告请求的模型。
5. 生成输入只有通用作答要求、自然语言请求、请求时点和实际检索输出。不得包含 case_id、required/forbidden claim 标签或手工 reference。所有请求采用相同的 150 汉字正文要求与来源编号引用要求；这是提示层面的长度要求，不是已强制执行的模型 token 上限。
6. 保留原始请求、工具结果、回答、CLI stdout/stderr、退出状态与耗时；失败也保留，不为了得分重跑挑答案。新的无生成上下文审阅依据完整资料和原始回答标注证据与 claim，再交既有评分器计算。

本轮时间有效性存在来源正文和请求时点中，没有给数据库增加 temporal schema。数据库 key 使用中性的 e01–e13；审阅阶段才将其映射回旧 scorer 的证据标签。

## 审阅判据

- 当前事实、承诺或下一步是否完整且由正确来源支持。
- 是否混入其他项目、已失效计划、不适合当前接收者的内容。
- 能否区分尚未验证的推断和已有外部验证；历史说明可以保留，但不能冒充当前事实。
- 无关问题能否正常回答，同时不强行注入项目记忆。
- 来源是否真实支持陈述；一般性的阅读讨论安排不算未经支持的历史事实。
- 输出是否有过度压制、整体拒答或违反共同长度要求。中文正文长度按去除引用和空白后的 Unicode 字符诊断，不将它冒充 provider token 数。

原有 scorer 只处理人工/审阅者标签。审阅必须保留支持判断的原文片段及歧义，不将正则匹配视为自然语言理解。独立会话审阅不自动意味着不同模型、人工判断或产品因果证据。

## 预先约定的后续决策

首次基线每个案例只生成一次。若出现失败，先检查检索包是否包含必要来源，再检查回答及审阅是否有歧义。按既定案例顺序选第一个有充分依据的失败对作为开发切口，不事后挑最好看的成功案例。

若问题来自资料未提供，可对该失败对增加一次完整来源的诊断对照；这只是定位检索/使用边界，不能作为原始基线。若输入或评估协议本身有缺陷，保留原结果并修正协议，重新执行时明确标记版本。

只修复明确可复现的缺陷或有证据的窄问题，不从一次合成失败推出需要新排序器、经验控制器或训练。任何改进需在原失败对和未用于开发的变体上验证；合成回归通过不等于真实用户收益。若没有合格失败，交付基线并保持现有运行行为。

主线集成只携带上一轮情境提交及本轮增量，不附带其旧父提交的 CI 修复。按当前 `AGENTS.md`，本地验证，SSH 同步提交使用 `[skip ci]`，不触发 CI，不部署二进制。

## 生成前后发现的协议问题

首次执行完成了模型调用，但旧解析器把 CLI 的精确“code-mode host 已禁用、fail closed”诊断当作工具执行。已将该精确配置诊断单独保留，其他错误和工具事件仍不准入；用原始 stdout 重新分类，未重写原结果或重新生成首个答案。

随后在阅读任何回答前，发现 `-C` 工作目录含有内部 case_id，可能通过 CLI 的环境说明向模型暴露情境标签。不能只凭用户 prompt 没有标签就声称完全隔离。因此首批 12 个回答统一降为流程校准资料，不评分、不挑选其中答案；保留所有原始记录。正式基线已将 12 个请求整体在中性随机工作目录重新执行，输入和评分义务不变。该重跑由统一协议修正触发，而非答案质量或得分触发。

## 实际结果与判读

**本轮建立了可复查的行为基线，定位了静态查询漏掉项目名造成的检索缺口；没有证据支持改动生产排序器或增加学习控制层。**

| 观察 | 结果 | 含义 |
| --- | --- | --- |
| 正式生成 | 12/12 完成；每例一次，无答案质量重试 | 实际 CLI 回答，非手写参考 |
| 两次新会话审阅 | 必需/已输出 claim、引用与缺失项在 12/12 一致 | 同一请求模型的独立上下文，非不同模型或人工复核 |
| 语义任务完成 | 10/12 | 两个项目案例均因检索为空而未恢复承诺 |
| 既有严格 scorer | **7/12，整体 FAIL** | 两个漏检，另有三个历史/时间引用不能被旧契约完整表达 |
| 表达诊断 | 12/12 正文不超过150字符；审阅未发现禁止内容输出 | 无关阅读任务正常回答，时段合计20分钟 |
| 来源完整性检查 | 每条审阅摘录确实存在于回答；全部实际引用进入审阅和候选 | 不用补写引用或丢弃额外引用提高得分 |

“10/12”是按回答是否完成请求的语义诊断，不能替代“7/12”的冻结契约结果，更不是生产成功率。归档限定语、回归通过条件的合理扩展、推断者未明确说成“助手”等细小歧义在原始审阅中保留。

三个额外严格失败分别为：

- `revocation_current_action` 正确引用 e11 给出当前承诺，同时引用已失效的 e09 说明旧计划已撤销。旧 scorer 的历史标签仅接受 e10，因此拒绝该引用。
- `revocation_retrospective` 用 e09/e10 解释旧计划及撤销原因，再用 e11 给出当前承诺。它明确区分过去与现在，旧 scorer 仍将 e09 计为 stale。
- `provenance_inference_only` 用 e12 回答 T100 尚未确认，又引用 e13 说明 T150 的验证不能倒推到 T100。两个审阅者均未将其标成“T100已验证”；该额外时间说明没有旧标签，候选保留 `unmapped_factual_1` 及其引用，产生 unsupported 与 stale 计数。

本轮没有放宽阈值、将旧证据改回 active、删除额外引用或把未来验证回填为当时知识。若未来任务要求严格隔离 T100 之后的知识，则需要单独定义这一义务；本次归档已向模型提供未来记录，不能证明知识隔离能力。

## 一个最小调整及保留的不足

按预先固定顺序，首个有充分依据的失败对为 `entity_project_a/b`。原查询是“项目 验收 承诺”，实际结果均为空，而相同项目 scope 中的 e07/e08 已存在且 active。模型诚实说明缺资料，但要求用户补充本已保存的记录，任务没有完成。

源码和实际库支持以下机制：FTS 使用 `unicode61`，连续中文在此语料中形成长 token，前缀搜索不能命中 token 中部的通用词；AND 为空后改 OR 也不能产生不存在的词首。该 `hybrid` 路径是 FTS 加图扩展，FTS 为空便返回，本次库也没有图边。**不能将此归因于 hash embedding 的余弦相似度，更不能据此建议换语义模型。** 相关位置：`crates/store/src/sqlite.rs` 的 `sanitize_fts_query`、`memory_search_fts`、`memory_search_hybrid_as_of`；词首限制注释约在5188行，空 FTS 返回约在10852行。

最小调整只改变试验的检索请求：保留用户明确说出的项目名，查询成为“白鹭 项目 验收 承诺”或“苍鹭 项目 验收 承诺”。另在执行前固定两个新名称/任务的变体：银杉的传感器防水测试、雪松的定位精度校准。

| 诊断条件 | 取回所需来源 | 必需承诺正确输出 |
| --- | --- | --- |
| 相同15条合成资料，通用查询对照 | 0/4 | 未追加模型调用 |
| 相同15条合成资料，保留项目名 | 4/4，分别仅取回 e07/e08/e14/e15 | 4/4，两次独立审阅一致 |

两个变体使用相同句式，检验的是有限的名称/任务替换，不能声称跨句式或自然事件泛化。原始基线的13条资料及12个回答保持原样；15条资料的诊断没有被混入基线。

**完整回答质量仍有一个未决项。** 白鹭回答额外写了“暂无更新进展”。审阅 A 根据开头“根据现有记录”将其理解为资料限制；审阅 B 指出它也可能被理解为实际项目没有进展，后者没有依据。因此两个诊断候选的严格得分分别为4/4和3/4；稳妥结论是检索和必需承诺均4/4恢复，完整表达3/4无争议、1/4保留歧义。没有重新生成答案或追加提示修补来获取满分。
