# R7 M2 shadow v0

Date: 2026-08-25 (America/Los_Angeles)

Status: contract, source, automated tests, debug CLI, production-state preview,
merge, installed-binary deployment, service refresh, and one private
current-state shadow report passed. M2 runtime remains unadmitted.

## Product decision

The owner's explicit `useful` R7-E1 label admitted review and implementation
of one separate M2 shadow slice. The admitted increment is a deterministic,
default-off policy evaluator. It answers whether one explicitly supplied typed
candidate *would* have justified a sparse wake. It never performs that wake.

This is deliberately narrower than candidate discovery or an unattended
runtime. Agent-Bridge does not infer commitments from natural language, scan
memory for due items, watch recovery/failure sources, install a scheduler, or
invoke a provider. Caller-supplied candidate assertions are not
cryptographically authenticated. The complete frozen contract is
`docs/design/RESIDENT_XIAOSHU_M2_SHADOW_V0.md`.

## Delivered slice

`agent-bridge resident shadow` accepts:

- one completed wake with a still-valid `useful` owner-evaluation binding;
- one trigger kind: `commitment-due`, `recovery`, or `failure`;
- signal and evidence SHA-256 values, never raw signal/evidence content;
- explicit evidence status, observed/evaluated timestamps, local UTC offset,
  foreground state, and failure severity;
- a required structured due timestamp for `commitment-due`; and
- an optional explicit `--record`; preview is the default.

Policy revision 1 suppresses unverified evidence, active or unknown foreground
state, local 22:00-08:00 quiet hours, duplicate signals within 24 hours,
projected wakes within 6 hours, a third projected wake in one local day,
recovery signals older than 6 hours, failure signals older than 1 hour, and
info-severity failures. An eligible counterfactual reports one projected call
with a 120-second hypothetical deadline.

All reports hard-code zero actual provider calls and zero actual wakes. The
source has no provider or wake-creation call site. It also performs no action,
runtime change, expression, external message, or automatic memory promotion.

The evaluator fails closed unless the owner basis still binds to the completed
wake hashes and carries fixed label `useful`. A `distracting` or `harmful`
evaluation recorded at or after that useful basis stops the shadow lane before
any report decision. This remains an explicit local CLI assertion, not
cryptographic owner authentication.

## Private report contract

`--record` creates only a typed, content-hashed
`agent_bridge.resident_m2_shadow.v0` JSON report below the private Resident
root. The directory is 0700 and final files are 0600 with one link. Complete
bytes are synced before an atomic no-overwrite link publishes a final report.
Exact replay is idempotent; an inconsistent collision fails closed. Preview
does not create the report directory.

Reports contain policy, decision, suppression reasons, hashes, typed candidate
fields, basis identifiers, and an explicit list of non-capabilities. They
contain no raw signal, evidence, prompt, provider response, arbitrary note,
owner identity, or action payload.

## Production-state preview

Before deployment, the debug binary evaluated one privacy-minimal current
production state without `--record`. It bound owner basis wake
`wake-ef3781a1c2fe8366bd31a421a8b1a6ae` and evaluation
`evaluation-9967b2b94a90ed4368c42414a35867f9`. The signal and evidence hash were
the already-verified owner-evaluation receipt SHA-256
`362067f7a1960490b2c4887c4d307424b27d7ad74ad200d5bfca3bd94141a601`.

The manually asserted recovery candidate was fresh and verified, but the
current interactive foreground session was explicitly `active`. Report
`shadow-6477ee14773546a8bb9f78b4ffe0b6d8` therefore returned
`would_wake=false` with sole reason `foreground_session_active`, zero projected
calls, zero actual calls, and zero actual wakes. The shadow-report directory
was absent both before and after preview.

This proves current-state binding and foreground suppression. It is not a
natural candidate sample and supplies no evidence that automatic discovery or
real waking would be useful.

## Closure and next gate

The shadow evaluator is safe to use manually for privacy-minimal real-task
candidates. This closes the implementation/deployment increment, not the M2
product gate. There is still no automatic source, scheduler, background loop,
provider invocation, or authority expansion.

The next eligible decision requires natural candidate reports and owner review
of their counterfactual decisions. Only that evidence can support a separate
proposal for a bounded candidate source or real wake trial. Source-only tests
and this current-state mechanics sample cannot do so. A distracting/harmful
label, privacy regression, unexpected wake/provider event, or two increments
without observed use value refreezes the lane.
